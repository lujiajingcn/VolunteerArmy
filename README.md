# VolunteerArmy · 断头谷公路 · 第一人称伏击战

一个**单文件 HTML5 第一人称战术射击游戏**。你是一名伏击小队的队长，端着步枪蹲在「断头谷公路」两侧的土坡上，用**中文语音**给队员下令，拦停敌军车队、炸毁坦克、夺取密码箱，然后带人从隘口撤离。

浏览器双击打开即玩 —— 无构建、无外部依赖、无服务器、离线可用。

## 玩法

**任务**：在公路两侧设伏，等车队进入伏击圈后起爆地雷截断车队，击毁坦克，拿到密码箱，带至少 6 人从撤离点撤出。

**关键纪律**：`沉住气，不要提前开火`。暴露过早，车队会强行冲过西侧出口，任务直接失败。

你不是俯瞰战场的指挥官 —— 你和队友一样站在土坡上，只有**眼睛和无线电**。看不到的敌人，就得靠队友报方位。

## 操作

| 键位 | 作用 |
|---|---|
| `点击画面` | 锁定鼠标视角（`ESC` 释放） |
| `W` `A` `S` `D` | 移动（相对视角：`W` 沿视线前进、`A`/`D` 横向平移） |
| `Shift` / `Ctrl` | 疾跑 / 蹲下（蹲下降低被弹面积与暴露） |
| `鼠标左键` | 射击 |
| `鼠标右键` | 瞄准（ADS，视野收窄 + 后坐力减小） |
| `R` / `G` | 换弹 / 手雷 |
| `F` | 快捷起爆 |
| `V` | **按住说话**（语音下令，需授权麦克风） |
| `Q` | 指令面板（点选下令，语音不可用时的主力手段） |
| `T` | 文本下令（打字输入，与语音走同一套解析器） |
| `1` `2` `3` | 确认低置信度候选指令 |
| `Z` | 标记准星指向的位置（作为「这里 / 那个位置」的指令目标） |
| `Tab` | 战况总览 |
| `Space` | 暂停 · `+` `-` 时间加速 1x / 2x / 4x |

除了你自己，**其余 10 人全部由语音指挥**（AI 自主行动）。语音识别不可用（浏览器不支持 / 未授权 / 无麦克风）时，会自动降级到 `Q` 面板与 `T` 文本，功能完全等价。

## 指令语法

```
呼号 + 动作 + 目标/地点（+ 修饰）
```

例：`老白起爆` · `反坦克组打坦克` · `全体打卡车` · `老周压制三点方向` · `铁头搬密码箱` · `全体撤离`

- **呼号**：10 个队员名 + 5 个编组（1 组 / 2 组 / 火力组 / 反坦克组 / 支援组），支持模糊匹配（喊错一个字也能识别）
- **动作**：移动 / 战斗 / 支援 / 状态报告 / 全体 / 紧急六类，每类含同义词
- **目标**：你按 `Z` 标记的准星落点、地点名、12 点方向、兵种名词（坦克 / 装甲车 / 卡车 / 军官 / 机枪手 / 步兵）
- **容错**：置信度 ≥ 70% 直接执行；低于阈值时弹出前 3 个候选让你按 `1/2/3` 确认；炮击、爆炸、机枪声会降低识别率，此时喊「重复」很有用

## 队友 AI

四层架构（感知 / 决策 / 行动 / 通讯）+ 16 个核心状态，行为不是脚本硬编码：

- **服从度**：`0.8 + 士气 − 危险 − 被压制` → `>0.6` 立即执行、`0.3~0.6` 延迟执行、`<0.3` 拒绝（会回话告诉你为什么不干）
- **目标选择优先级**：玩家指定 > 正在攻击队友的敌人 > 角色职责（反坦克手找坦克、狙击手找军官/机枪手、机枪手找步兵群）> 最近威胁
- **掩体评分**：`防护 + 隐蔽 + 射界 + 撤退路线 − 距离 − 暴露时间`，AI 会自己抢能打到人又有掩护的位置
- **视线三层**：`losFire`（只有硬掩体和烟雾真的挡子弹）/ `losSight`（树冠在远距离遮蔽观察）/ `losBlocked`（完全看不见）

## 关卡

「断头谷公路」——A 到 G 七个关键点 + 部署区 + 撤离点。

- 车队 6 辆车按固定顺序通过：先头吉普 → 装甲车 → **坦克** → 卡车 → 装甲车 → 后卫吉普
- 敌人有分阶段的反应：遇袭 0–2 秒停车混乱 → 步兵下车散开 → 呼叫增援
- 8 个脚本事件、10 分钟时间线、S/A/B/C 评分
- **每局随机变体**：天气（晴 / 雨 / 夜）、车队顺序、敌方步兵 10–16 人、地雷点位、密码箱位置（卡车后厢 / 装甲车 / 军官随身）、增援时间

密码箱位置直接改变打法：锁在卡车里就得把卡车打爆，军官随身就得先狙掉军官 —— 开局情报会告诉你这一局是哪一种。

## 画面：手写的原生 WebGL 渲染器

**零依赖是硬约束**，所以没有引 Three.js —— 整个 3D 管线是 `index.html` 里手写的原生 WebGL 1.0：

- **自带 mat4 数学库**（`m4persp` / `m4lookAt` / `m4mul` / `m4trs` / 投影到屏幕的 `projectPoint`）
- **程序化纹理**：草地 / 沥青 / 泥土 / 树皮 / 帆布 / 水面，全部用离屏 canvas 现场画出来，不加载任何图片
- **静态世界烘焙成一个网格**：地形、公路条带、河流、桥、全部树木岩石油桶（`n=11292`）各自只占一次 draw call；整帧约 **22–23 次绘制**
- **地平面就是 2D 世界平面**：`(x, y) → (x, 0, y)`，比例尺 **1 米 ≈ 20 世界单位**（公路宽 140 ≈ 7 米），逻辑层不需要任何坐标换算
- **第一人称相机**：指针锁定驱动偏航/俯仰，走路摇晃、后坐力、ADS 插值、受击抖动、受伤时屏幕边缘泛红
- **逻辑层与渲染层严格分离**：渲染层每帧只做两件「回写」——把 `Cam.yaw` 写进 `u.facing`，把 `Cam.pitch` 写进 `World.viewPitch`（用于按俯仰角折算弹道射程）。渲染层删掉，战斗逻辑照样能在 Node 里跑完整局

HUD 是 DOM（面板）+ 2D canvas（世界内标记、曳光、准星）两层：现代战争写实风格 —— 冷灰蓝、极简、无血条、菱形目标标记、无线电字幕。

## 音效：同样是零依赖的程序化合成

**没有加载任何音频文件**（否则就不再是「单文件、离线可用」）。所有声音都在这份 HTML 里用 Web Audio API 现场合成：

- **枪声三段式**：枪口爆音（带通噪声）+ 高频锐度（高通噪声）+ 胸腔低频（三角波）。步枪 / 机枪 / 狙击 / 敌方枪械各有一套滤波与包络参数，听得出是谁在打
- **爆炸按当量分档**：低频冲击波 + 低通噪声 + 破片高频 + 山谷余响；地雷 / 油桶 / 手雷 / 火箭弹 / 炮弹 / 车辆殉爆 / 坦克炮各一档，外加金属撕裂成分
- **机械音**：换弹（多段咔哒）、命中金属、命中肉体、尸体倒地、箱子落地
- **通讯音**：无线电上行/下行提示音（静噪咔哒开头收尾）、指令面板提示、结算与胜败 sting
- **空间化**：按 `距离衰减 + 空气吸高频（低通截止随距离下移）+ 立体声像` 定位；听声即可判断来向
- **动态处理**：主总线挂 `DynamicsCompressor`，近距爆炸触发 ducking 压低其他声音，并叠加短促耳鸣（走独立总线，不被压限吃掉）
- **循环层**：风声 + 雨声底噪随天气切换，夜战带断续虫鸣；敌方车辆未入视野时，引擎轰鸣是唯一的方位线索（按距离/车型/车速实时调参）
- **限流**：同类音效有最短触发间隔（全队机枪齐射会被合并）、每 0.1 秒最多合成 26 条、超出 `max` 距离整条剔除 —— 防止削波爆音与主线程卡顿
- **可访问性与降级**：顶栏音量滑块 + 静音按钮，偏好存 `localStorage`；`AudioContext` 不可用（老浏览器 / 隐私模式）时整层静默降级，战斗逻辑完全不受影响

浏览器要求音频上下文诞生于用户手势，因此 **点「开始任务」后才出声**（`bootAudio()`）。音频层与战斗代码之间只有 `sfx(id, x, y, opt)` 一个接口：战斗代码不关心音频是否可用，也绝不等它返回。

## 语音：授权只走一次，不会反复弹窗

`V` 按住说话走的是 Web Speech API。这里踩过一个坑，值得写清楚，免得以后改回去：

**症状**：按下 `V` → 浏览器弹「想要使用麦克风」→ 点「允许」→ 松手后再按 `V`，**又弹一次**，永远进不去。

**根因**：Chrome 的麦克风授权弹窗是挂在「那一次识别会话」上的。原实现是按住 `V` 就 `recog.start()`，弹窗一出来玩家得松手去点「允许」—— 而 keyup 会调 `stopVoice()`，把这次待授权的会话连同授权请求一起中止，授权随之作废。再按 `V` 又发起全新请求，于是循环。

**修法四条**：

1. 授权改由**独立的 `getUserMedia`** 走 —— 它是个 promise，不挂在识别对象上，松手不会中止它；
2. 拿到的 `MediaStream` **全程保留、故意不 `stop()`** —— 只要这根流还在，本页麦克风权限就一直有效，之后每次 `recog.start()` 都不再弹窗（`file://` 下尤其重要，Chrome 不持久化 `file://` 的授权）；
3. `start` / `stop` 加状态机 —— 按住 `V` 时 `keydown` 会自动重复，不能让它把 `start()` 打成一串；
4. 本页状态（`listening`）**自行维护、不押在 `onend` 上** —— 识别服务异常时 `onend` 可能永不到达，若只等它复位，`listening` 会永久为 `true`，之后每次按 `V` 都被空转守卫挡下，语音就此彻底哑掉。

**降级**：`麦克风未授权 / 无设备 / 浏览器不支持 / 语音服务连不上` 都会在字幕里明确告知，并指向 `Q` 面板与 `T` 文本（同一套解析器，效果完全等价）。语音条左侧的圆点会随状态变色：**青 = 正在聆听 · 黄 = 等待授权 · 红 = 未授权（点它可重试）**。

> **`file://` 提示**：直接双击打开时，Chrome 出于安全策略可能不记住 `file://` 页面的麦克风授权。若反复被问，建议用本地服务器打开（如 `python -m http.server`），或直接用 `Q` / `T`。

## 项目结构

```
index.html            游戏本体（单文件，约 281 KB）
README.md
_devcheck/            离线验证管线（不需要浏览器）
  extract.js          从 index.html 抽出内联脚本 → _all.js / _logic.js
  test.js             90 条单元断言（解析器、状态机、伤害链路、回归）
  sim.js              端到端战场仿真，3 个剧本
  sweep.js            10 个随机种子的平衡扫描（看胜率，不看单局运气）
  render_smoke.js     渲染层冒烟测试：WebGL/DOM 桩 + vm 沙箱里真跑整份脚本
  audio_smoke.js      音频层冒烟测试：桩 AudioContext 跑全部音色，查参数非法与 id 漏配
  browser_probe.js    真实浏览器端到端探针：headless Edge/Chrome + CDP，验证 AudioContext 真的建起来
  voice_probe.js      真实浏览器探针：实测 file:// 与 http:// 下的麦克风授权行为
  voice_flow.js       真实浏览器语音流程验证：复现「反复弹授权框」并验证修复（20 条断言）
  shot.js             Playwright + Chromium 真实截图验证（SwiftShader 软渲染）
  png.py              纯 Python PNG 解码器（不依赖 PIL，用于精确取像素）
```

## 验证管线

```bash
cd _devcheck
node extract.js                  # 抽取内联脚本
node --check _all.js             # 整份脚本语法校验（含渲染层）
node test.js                     # 90 条断言
node sim.js                      # 三个剧本端到端仿真
node sweep.js                    # 多种子平衡扫描
node render_smoke.js             # 渲染层在 Node 沙箱里真跑一遍
node audio_smoke.js              # 音频层：全部音色 + 空间化条件 + 限流 + 静音
node browser_probe.js            # 真实浏览器：WebGL + AudioContext + 音量控件（39 条断言）
node voice_flow.js               # 真实浏览器：语音授权流程，复现「反复弹框」bug 并验证修复（20 条断言）
node shot.js                     # 真实浏览器截图 → shots/*.png
```

这套管线分三层，各管一件事：

| 层 | 工具 | 能挡住什么 |
|---|---|---|
| 语法 / 断言 / 仿真 | `extract.js` `test.js` `sim.js` | 逻辑回归、平衡崩坏、AI 走进死循环 |
| Node 沙箱冒烟 | `render_smoke.js` `audio_smoke.js` | 渲染层崩溃；音频层的参数非法、音色 id 漏配 |
| 真实浏览器 | `browser_probe.js` `voice_flow.js` `shot.js` | **「能跑」但「不对」** —— 画面被遮挡、颜色错、HUD 压住准星、音频图没连上、授权流程死循环 |

`audio_smoke.js` 值得单独说一句：它会从 `index.html` 里把所有 `sfx('字面量')` 调用点抽出来，逐个核对音色表里是否真有实现。**打错一个字母，那条音效就永远不会出声，而且几乎不可能靠听发现** —— 这个检查就是为它写的（它确实抓到过一次：`BOOM` 爆炸参数表定义了却漏接进 `SYN` 音色表，导致所有爆炸静默）。

`voice_flow.js` 则是为「反复弹授权框」这个 bug 写的回归护栏：它用 `--use-fake-ui-for-media-stream` 让浏览器自动同意授权（等价于玩家点了「允许」），并把 `getUserMedia` 与 `recog.start()` 包上计数器，然后逐个场景断言——**正常按住说话只请求一次授权**、**授权请求还没返回就松手，授权仍然作废不了（核心场景）**、**授权被拒后连按 4 次 `V` 不得再触发任何请求**。权限这类 bug 用肉眼和单测都抓不住，只能靠真实浏览器里的调用计数来钉住。


`sim.js` 的三个剧本对应三种打法语义：

| 剧本 | 期望结果 |
|---|---|
| A 标准伏击 | 伏击成功 · 坦克毁 · 密码箱到手 · ≥6 人撤离 |
| B 提前开火 | 失败（车队冲卡） |
| C 全程不接战 | 失败（车队通过西侧出口） |

前两层能挡住「改错了眼睛看不出来」的地方；**第三层才能挡住「眼睛看得出来、但逻辑和冒烟测试都发现不了」的地方** —— 例如相机被自己角色的模型包住、天空渐变方向画反。截图脚本因此不只是「截图」，还会收集 `console.error` / `pageerror` 并以退出码反映。

## 环境要求

任何支持 WebGL 1.0 与现代 JS 的浏览器（Chrome / Edge 最新版即可）。语音功能依赖 Web Speech API，**Chrome / Edge 支持最好**。

验证管线需要 Node.js（本项目在 Node 22 上验证通过）；`browser_probe.js` 需要本机装有 Edge 或 Chrome（走 CDP，无需额外依赖），`shot.js` 需要 Playwright + Chromium。
